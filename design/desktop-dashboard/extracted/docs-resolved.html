Worktrees

What a worktree contains

A worktree is one task made concrete: a git branch, a working copy on disk, the agent session that works in it, and the issue it belongs to. Opening the worktree opens all four.

Lifecycle

Trail creates the worktree from development when a task is picked up. The agent works there and opens a draft pull request. After the pull request merges, Trail removes the worktree and moves it to Remote worktrees as history.

Where fixes land

A fix found locally lands on development. A fix found on production lands on development first and is then brought to main, so both stay in step.
